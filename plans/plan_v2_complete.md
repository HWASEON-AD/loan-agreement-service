## 1. 도메인 연결 가이드

### 현황

현재 서비스 기본 URL은 `https://loan-agreement-service.vercel.app` 이며,  
`lib/config.ts`의 `getBaseUrl()`이 `NEXT_PUBLIC_BASE_URL` 환경변수를 참조한다.  
도메인 미연결 상태로 서비스가 운영 중이다.

---

### 1-1. 추천 도메인 후보

서비스명 "내지마요"는 "세금/증여세를 내지 않아도 된다"는 감성적 메시지를 담고 있다.  
차용증, 가족 대여, 세무 상담을 메인으로 하는 법률·금융 서비스이므로 신뢰감 있는 도메인이 중요하다.

| 우선순위 | 도메인 | 이유 |
|---------|--------|------|
| 1순위 | `naejimayo.com` | 서비스명 그대로, 국제 확장성, .com 신뢰도 |
| 2순위 | `naejimayo.co.kr` | 국내 서비스 신뢰도 최고, 내국인 법률 서비스에 적합 |
| 3순위 | `내지마요.kr` | 한글 도메인 (검색엔진 노출 시 시각적 차별화, 단 일부 구형 브라우저 비호환) |
| 4순위 | `loanfree.co.kr` | 영문 브랜딩 병행 시 유용 |
| 5순위 | `taxfree-loan.com` | B2B 세무 파트너 유치 목적 시 고려 |

**최종 권장: `naejimayo.com` + `naejimayo.co.kr` 동시 취득 후 .com으로 리다이렉트**

---

### 1-2. 구매처 추천

| 구매처 | 특징 | 권장 용도 |
|--------|------|---------|
| **가비아 (gabia.com)** | 국내 1위 도메인 등록, .co.kr 등록 시 공인기관 위임 처리 간편 | .co.kr 취득 1순위 |
| **후이즈 (whois.co.kr)** | 국내 도메인 관리 편의성 높음, 기업 도메인 다수 보유 중 | .kr 계열 백업 |
| **Namecheap (namecheap.com)** | .com 최저가 (약 $10~12/년), WhoisGuard 무료, DNS 관리 UI 편의성 | .com 취득 1순위 |
| **Cloudflare Registrar** | 원가 공급, DNS 관리 일원화 가능 | 중장기 운영 안정화 후 이전 고려 |

**결론: `.com` → Namecheap, `.co.kr` → 가비아로 각각 구매**

### 1-3. Vercel DNS 연결 방법

연결 방식은 두 가지다. 서비스 상황에 따라 선택한다.

#### 방식 A — Nameserver 위임 방식 (권장, Namecheap 기준)

DNS 전체를 Vercel에 위임하는 방식. 서브도메인 관리가 가장 편리하다.

```
단계 1. Vercel 대시보드 → 프로젝트 선택 → Settings → Domains
단계 2. "naejimayo.com" 입력 후 Add
단계 3. Vercel이 제공하는 Nameserver 4개 복사
         예시: ns1.vercel-dns.com / ns2.vercel-dns.com
단계 4. Namecheap → Domain List → naejimayo.com → Manage → Nameservers
         "Custom DNS" 선택 후 Vercel Nameserver 4개 입력
단계 5. DNS 전파 대기: 최소 30분 ~ 최대 48시간
단계 6. Vercel Domains 탭에서 초록색 체크 확인
```

#### 방식 B — CNAME 방식 (기존 DNS를 유지하면서 일부만 Vercel로 연결)

이미 가비아에서 DNS를 사용 중이거나, 이메일 서버(MX 레코드)가 같은 도메인에 있는 경우 선택.

```
단계 1. Vercel 대시보드 → Settings → Domains → "naejimayo.com" 추가
단계 2. Vercel이 제공하는 값 확인:
         - @ (루트 도메인): A 레코드 → 76.76.21.21
         - www: CNAME → cname.vercel-dns.com
단계 3. 가비아/Namecheap DNS 설정 → 위 레코드 2개 추가
단계 4. 루트 도메인(@)은 CNAME 불가하므로 반드시 A 레코드로 입력
단계 5. www → naejimayo.com 리다이렉트는 Vercel이 자동 처리
```

**주의사항**
- SSL 인증서는 Vercel이 Let's Encrypt로 자동 발급 (별도 설정 불필요)
- .co.kr 도메인도 동일 프로젝트 Domains 탭에 추가해서 naejimayo.com으로 리다이렉트 설정 가능
- Vercel 무료 플랜은 커스텀 도메인 무제한 지원

**배포 재시작 필요:**

`vercel --prod` 로 수동 재배포 한 번 실행.

## 2. 로그인/인증 전략

### 현황

```
app/api/otp/send/route.ts   — 이메일로 OTP 발송 (10분 유효)
app/api/otp/verify/route.ts — 6자리 코드 검증 → agreement_id + signer_type 기반
lib/otp.ts                  — sendOtp(), verifyOtp() 함수
```

현재 인증 방식: **이메일 OTP만 존재**  
- 별도 회원 테이블 없음
- 약정서 ID + 서명 토큰(UUID)을 발급해서 당사자를 식별
- 로그인/가입 없이 이메일로 접속하는 1회성 플로우

---

### 2-1. 서비스 특성 분석

내지마요의 핵심 사용자 시나리오:

```
1. 대여자(갑)가 약정서 작성 시작 → 이름/이메일 입력 → OTP 인증 → 서명
2. 차용자(을)가 이메일 링크 클릭 → OTP 인증 → 서명
3. 결제 → 내용증명 발송
```

이 플로우에서 "계정"의 역할은 없다. 약정서 1건당 1회성 접근이 전부이며,  
동일 사용자가 여러 건을 작성해도 각 건이 독립적으로 처리된다.

---

### 2-2. 현재 OTP만으로 충분한지 여부

**결론: 현재 이메일 OTP만으로 충분하다. 단, 마이페이지 기능 추가 시 재검토 필요.**

| 시나리오 | OTP 충분 여부 | 이유 |
|---------|--------------|------|
| 단건 약정서 작성/서명 | 충분 | 이메일 본인확인으로 서명 증거 확보 가능 |
| 약정서 PDF 재다운로드 | 충분 | 서명 토큰(UUID)으로 접근 가능 |
| 내 약정서 목록 조회 | 부족 | "내 이메일로 만든 약정서 전체"를 조회하려면 계정 필요 |
| 만기 알림 수신 | 충분 | 이메일 발송으로 처리 가능 |
| 갱신 신청 | 충분 | 이메일 링크 + 원본 약정서 ID로 처리 가능 |
| 세무상담 신청 | 충분 | 이름/이메일/전화번호 폼 제출만으로 충분 |

---

### 2-3. 소셜 로그인(카카오/구글) 필요 여부

**결론: 현재 단계에서 소셜 로그인은 불필요하며, 오히려 역효과 가능성 있음.**

이유:
1. **서비스 대상이 4050세대 중심**: 가족 간 금전 거래는 주로 40~60대가 처리. 카카오/구글 OAuth 연동보다 이메일이 더 친숙함.
2. **법적 증거 효력 강화**: 이메일 OTP는 "특정 이메일 계정 소유자"를 증명하는 증거로 활용 가능. 소셜 로그인은 OAuth 공급자 의존성 증가.
3. **개인정보 최소 수집 원칙**: 소셜 로그인 시 프로필 정보(사진, 닉네임 등) 수집 필요 → 개인정보처리방침 복잡해짐.
4. **마이페이지 없는 구조**: 로그인 상태를 유지할 이유가 없음.

**소셜 로그인을 고려해야 하는 시점:**
- 월정액 구독(이자 관리 기능) 출시 시
- 약정서 여러 건 관리 '마이페이지' 출시 시
- B2B(세무사/법무사 파트너 포털) 확장 시

---

### 2-4. 권장 인증 방식 정리

| 기능 | 권장 방식 | 비고 |
|------|---------|------|
| 약정서 서명 | 이메일 OTP (현행 유지) | 법적 증거로 활용 |
| 어드민 접근 | 비밀번호 (현행 유지) | ADMIN_PASSWORD 환경변수 |
| 세무상담 신청 | 폼 제출 (인증 불필요) | 이메일/전화 제출로 충분 |
| 갱신 플로우 | UUID 토큰 + 이메일 OTP | 보안성 유지 |
| 향후 마이페이지 | 이메일 Magic Link (Supabase Auth) | 필요 시 추가 |

## 3. 전자서명 법적 검토 (모두싸인 동등성)

### 현황


**감사추적인증서에 포함된 정보:**
- 서명자 이름, 연락처(마스킹), 이메일(마스킹)

- IP 주소, User-Agent (접속 기기)
- 이메일 OTP 인증 여부
- 문서 해시값 (SHA-256)
- 수기서명 이미지

---

### 3-1. 전자서명법 제3조 '일반 전자서명' 요건 분석

전자서명법 제3조는 전자서명을 **공인 전자서명**과 **일반 전자서명**으로 구분한다.  
2020년 전자서명법 전부개정 이후 공인인증서 독점 지위가 폐지되었고,  
**일반 전자서명도 당사자 합의 및 신뢰성 요건을 충족하면 법적 효력을 갖는다.**

**전자서명법 제3조 일반 전자서명 요건:**

| 요건 | 내용 | 현재 구현 충족 여부 |
|------|------|-------------------|
| 서명자 확인 | 서명이 서명자에 의한 것임을 확인할 수 있어야 함 | 이메일 OTP + 수기서명 이미지로 충족 |
| 위변조 검지 | 서명 후 문서 변경 여부를 검지할 수 있어야 함 | SHA-256 해시 + 서명 시점 고정으로 충족 |
| 부인방지 | 서명자가 사후에 부인하기 어려워야 함 | IP, UA, OTP 로그, 서명 이미지로 충족 (부분) |
| 감사 가능성 | 서명 사실을 사후에 확인·검증할 수 있어야 함 | 감사추적인증서 PDF로 충족 |

**결론: 전자서명법 제3조 일반 전자서명 요건은 대부분 충족된다.**

---

### 3-2. 모두싸인과의 기술 수준 비교

| 항목 | 모두싸인 | 내지마요 현재 |
|------|---------|-------------|
| 서명자 확인 방법 | 이메일 OTP + 휴대폰 인증 선택 | 이메일 OTP 필수 |
| 문서 무결성 | AES-256 암호화 + 해시 | SHA-256 해시 |
| 타임스탬프 | RFC 3161 신뢰 타임스탬프 기관 | 서버 시간 기록 (신뢰 타임스탬프 미적용) |
| 감사 추적 | 서버 로그 + 인증서 PDF | Supabase DB + 감사추적인증서 PDF |
| 인증서 수준 | AATL(Adobe Approved Trust List) 인증 없음 | AATL 인증 없음 (동일) |
| 법원 제출 경험 | 다수 판례에서 인용 | 판례 없음 (신규 서비스) |
| 보험/보증 | 일부 요금제에 법적 보증 포함 | 없음 |

**핵심 차이: RFC 3161 신뢰 타임스탬프 미적용**

모두싸인도 AATL 인증을 받지 않는다. 법적 효력의 핵심 차이는  
**RFC 3161 기반 공인 타임스탬프** 적용 여부다.

---

### 3-3. 법적 리스크 및 충분성 판단

**현재 구현의 법적 충분성:**

가족 간 차용증의 법적 분쟁 가능성은 낮다. 국세청 세무조사 대응 목적으로  
"작성 사실의 증거"가 필요한 것이 핵심이며, 이 목적에는 현재 구현이 충분하다.

| 상황 | 현재 구현 충분성 | 비고 |
|------|----------------|------|
| 국세청 세무조사 대응 | 충분 | OTP 기반 이메일 인증 + 해시 + IP 로그 |
| 민사소송 (당사자 부인) | 조건부 충분 | 서명 이미지 + OTP 로그로 진정성 추정 가능 |
| 공증 대체 | 불충분 | 공증은 법무사/공증인 필요, 이 서비스로 대체 불가 |
| 형사 사기 증거 | 조건부 충분 | 디지털 증거 원칙에 따라 법원 판단 |

**권장 법적 보완 조치 (우선순위순):**

1. **이용약관 명시**: "본 서비스의 전자서명은 전자서명법 제3조에 따른 일반 전자서명입니다"
2. **RFC 3161 타임스탬프 추가** (선택사항): FreeTSA.org 등 무료 TSA 활용 가능, 법적 신뢰도 향상
3. **SMS OTP 추가 인증** (선택사항): 이메일 OTP + SMS OTP 2중 인증 시 부인 가능성 대폭 감소
4. **공증 서비스 파트너 연계 안내**: 공증이 필요한 고액 건(5,000만원 이상)은 법무사 연결 유도

**최종 판단:**  
현재 구현은 서비스 출시 초기 단계로서 법적으로 충분하다.  
모두싸인 수준의 법적 효력 차이는 실무적으로 크지 않으며,  
가족 간 차용증의 세무 목적에서는 현행 구현으로 충분히 대응 가능하다.

## 5. 고객 갱신(재신청) 기능 구현

### 현황

약정서 만기 알림 기능이 없고, 갱신 플로우가 없다.  
만기가 된 약정서는 국세청 세무조사 시 "대여금이 아닌 증여"로 오인될 수 있어  
갱신/연장은 세금 리스크 방어에 필수적이다.

### 결론/판단

만기 알림 + 갱신 플로우는 서비스의 LTV(고객 생애 가치)를 늘리는 핵심 기능이다.  
기존 고객이 재결제하는 구조이므로 CAC(고객 획득 비용) 없는 수익이 발생한다.

---

### 5-1. DB 변경

```sql
-- agreements 테이블 컬럼 추가
ALTER TABLE agreements
  ADD COLUMN IF NOT EXISTS parent_agreement_id UUID
    REFERENCES agreements(id) ON DELETE SET NULL;

-- 만기 알림 발송 기록 테이블
CREATE TABLE IF NOT EXISTS expiry_notifications (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  agreement_id    UUID NOT NULL REFERENCES agreements(id) ON DELETE CASCADE,
  notify_type     TEXT NOT NULL,  -- '30d' | '7d' | '0d'
  sent_at         TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  email_to        TEXT NOT NULL
);

CREATE INDEX IF NOT EXISTS idx_expiry_notif_agreement
  ON expiry_notifications (agreement_id, notify_type);
```

**실행 방식:** Vercel Cron Jobs (vercel.json에 설정) 또는 외부 크론(Claude Code CCR)

내용증명 서비스 BM: 결제 완료 고객의 약정서 + 내용증명을 우체국으로 발송해주는 것이 핵심 부가가치.

### 6-1. 우체국 내용증명 발송 절차

#### 온라인 발송 (epost.go.kr)

**1단계: 사이트 접속**
- URL: https://service.epost.go.kr
- 공동인증서(공인인증서) 또는 간편인증(카카오/네이버) 로그인 필요

**2단계: 내용증명 메뉴**
- 상단 메뉴: 우편 → 내용증명 → 내용증명 작성

**3단계: 문서 작성**
- 발신인 정보 입력 (이름, 주소, 연락처)
- 수신인 정보 입력 (이름, 주소)
- 내용증명 본문 직접 입력 또는 파일 첨부 (PDF/HWP/DOC)
- 최대 20페이지 / 파일 크기 5MB 이하

**4단계: 결제 및 발송**
- 결제 후 접수번호 발급
- 등기 우편으로 발송 (수신인에게 2~3 영업일 내 도착)

#### 방문 발송 (우체국 창구)

**준비물:**
- 동일한 내용의 문서 3부 (발신인 보관 1부, 수신인 발송 1부, 우체국 보관 1부)
- 발신인 신분증
- 내용증명 봉투 (일반 우편 봉투 사용 가능)

**절차:**
1. 우체국 창구 방문
2. "내용증명 우편 발송 요청" 안내
3. 문서 3부 + 발신인 정보 제출
4. 우체국에서 접수 확인 도장 날인 후 1부 반환
5. 접수번호 메모 (온라인 배송 조회용)

### 6-2. 비용 (2025~2026년 기준)

**온라인 (epost.go.kr):**
| 구분 | 금액 |
|------|------|
| 기본 요금 | 4,500원 |
| 1~4페이지 | 포함 |
| 추가 페이지 (5페이지부터) | 페이지당 200원 |
| 등기 배달 확인 | 500원 (선택) |
| **약정서 1건 발송 예상 비용** | **약 5,000~5,500원** |

주: 약정서는 일반적으로 2~3페이지이므로 기본 요금 내 처리 가능.

**방문:**
- 온라인과 동일 요금 구조
- 창구 수수료 없음 (온라인 편의 차이만 있음)

**현재 서비스 가격 vs 원가:**
```
SERVICE_PRICE = 0원 (무료 이벤트 중)
SERVICE_PRICE_ORIGINAL = 30,000원 (정가)
내용증명 실비 = 약 5,000원
마진 = 25,000원 (83%)
```

유료 전환 시 내용증명 실비를 제외하면 충분한 마진이 발생한다.

### 6-3. 법적 요건

**내용증명 작성 필수 요건:**

| 항목 | 기준 |
|------|------|
| 발신인 | 이름, 주소 명기 필수 |
| 수신인 | 이름, 주소 명기 필수 (정확한 주소 필요) |
| 문서 부수 | 동일한 내용 3부 (발신인 1부, 수신인 1부, 우체국 보관 1부) |
| 내용 | 법적 강제 형식 없음, 자유 서식 |
| 날짜 | 발송일 기재 권고 |

**법적 효력:**
- 내용증명 자체는 법적 강제력이 없다.
- 다만 "발송 사실과 내용을 우체국이 공식 증명"하므로, 분쟁 발생 시 핵심 증거가 된다.
- 특히 가족 간 차용 시 국세청이 요구하는 "금전소비대차 사실 증명"에 활용 가능.

**내지마요 서비스에서 내용증명의 의미:**
- 대여 사실을 제3자(우체국)가 날짜와 내용을 증명
- 국세청 세무조사 시 "증여가 아닌 실제 대여"를 입증하는 핵심 서류
- 수신인(차용자) 측에서도 "수령한 금액의 성격"을 명확히 함

### 6-4. 어드민 실무 체크리스트

```
내용증명 발송 업무 체크리스트 (건당)
─────────────────────────────────────

□ 1. 어드민 대시보드 → 주문 목록에서 결제 완료(paid) 상태 확인
□ 2. 약정서 PDF 다운로드 (상세 모달 → PDF 다운로드)
□ 3. 내용증명용 PDF 준비
     - 약정서 본문 PDF 사용
     - 표지에 "대여금 대여 사실 통보" 제목 추가 권고
□ 4. 발신인 정보: 대여자(갑) 이름, 주소
     수신인 정보: 차용자(을) 이름, 주소
□ 5. 온라인 발송 시
     - epost.go.kr 로그인
     - 내용증명 작성 → PDF 첨부
     - 결제 후 등기번호 확인
□ 6. 어드민 대시보드 → 해당 주문 → "발송 완료 처리"
     - 등기번호 입력
     - mark-sent API 호출 → 고객에게 등기번호 안내 이메일 자동 발송
□ 7. 발송 후 2~3 영업일 내 우체국 배송 조회 확인
     - https://service.epost.go.kr/trace.RetrieveDomesticObjectNumber.comm
□ 8. 수령 확인 후 orders.cert_mail_status = 'sent' 최종 업데이트
```

### 6-5. 향후 자동화 가능성

**우체국 epost.go.kr API 유무 조사:**

현재(2026년 6월) 기준, 우체국에서 법인/기업 대상으로 **'내용증명 기업 API'를 별도 제공하지 않는다.**  
대량 발송이 필요한 기업은 우편물 대행업체(예: 에이팝, 이지메일 등)를 통해  
프로그래밍 방식의 발송이 가능하다.

**자동화 방안 (3단계 로드맵):**

| 단계 | 방법 | 시점 |
|------|------|------|
| 1단계 (현재) | 어드민 수동 발송, 위 체크리스트 따름 | 즉시 |
| 2단계 | 우편 대행 API 서비스 연동 (에이팝 등) | 월 건수 20건 초과 시 |
| 3단계 | 자동화 파이프라인 구축 (결제 완료 → 대행사 API → 등기번호 수신 → 이메일 발송) | 월 건수 50건 초과 시 |

**우편 대행사 API 예시 (참고):**
- **에이팝(apop.co.kr)**: 공문서/내용증명 특화, 건당 발송 API 제공, 단가 약 8,000~12,000원
- **이지메일(ezmail.co.kr)**: 대량 등기우편 API, 기업 계약 필요

**2단계 전환 조건:**  
어드민 발송 건수가 주 5건 이상 되면 수동 업무 부담이 생기므로 대행사 API 연동을 검토한다.  
월 20건 × 12,000원 = 240,000원 (단가 상승을 서비스 가격에 반영해야 함).
