# 계약갱신 요구 통지서 기능 (2026-08-13)

주택임대차보호법 제6조의3 계약갱신요구권 행사 통지서를 **무료**로 만들어 주고,
인쇄·이메일·문자로 보낼 수 있게 하는 기능. 진입 경로 = 상단 네비 `계약갱신 요구 통지서` → `/renewal`

## 파일 구성

| 파일 | 역할 |
|---|---|
| `lib/renewal-calc.ts` | 행사기간 날짜 계산 **순수 함수**. LLM 호출 0회 |
| `lib/renewal-text.ts` | 통지서 본문 · 문자/카톡 요약 · 이메일 제목 생성 |
| `components/renewal/RenewalForm.tsx` | 한 페이지 완결형 입력 폼 (client) |
| `app/renewal/page.tsx` | 페이지 셸 + 메타데이터 + 고지 (server) |
| `app/api/renewal/send/route.ts` | 이메일 전송. **DB 미저장**, IP 10분 5회 레이트리밋 |
| `components/SiteHeader.tsx` | `NAV_ITEMS` 에 `/renewal` 등록 (데스크탑·모바일 공용 배열) |

## 🚨 계산 규칙 — 마감은 "응당일의 전날"

```
개시 = 만료일의 6개월 전 응당일 0시
마감 = 만료일의 N개월 전 응당일의 "전날" 24시까지 도달
```

- 민법 제157조(초일 불산입)를 **역산에도 유추적용**한 결과다.
  (대법원이 민법 제71조 '총회 1주간 전' 통지 사안에서 역산에 초일불산입을 적용한 법리)
- 응당일이 없는 달은 **그 달 말일**로 맞춘다(제160조③ 유추). 예: 2026-04-30의 2개월 전 → 2026-02-28 → 전날 2026-02-27
- 마감을 "응당일 당일 24시"로 보는 견해도 실무에 있으나, **이용자가 하루 손해 보는 쪽(더 이른 마감)** 을 채택했다.
  늦은 마감을 표시했다가 틀리면 권리 상실이고, 이른 마감은 하루 일찍 보낸 것에 그친다.
- 민법 제161조(말일 공휴일 익일 연장)는 역산 적용이 보장되지 않아 **미적용**.

### 경과규정 분기 (2020-12-10)

부칙(법률 제17363호) 문언 = "이 법 시행 후 최초로 **체결되거나 갱신된** 임대차".
기준은 기간 개시일이 아니라 **체결(갱신) 시점**이다.

- 체결·갱신일 ≥ 2020-12-10 → **2개월** 규칙
- 그 이전 → **1개월** 규칙 (화면에 "작성일이 정확한지 확인" 경고를 함께 띄운다. 오입력 개연성이 더 높다)

## ⚖️ 법적 안전선 — 수정 시 반드시 지킬 것

대법원 리걸테크 '로폼' 사건(심리불속행 기각 확정)이 그은 선 위에 설계했다.

- ✅ 합법 = 이용자가 선택한 유형 + 입력값을 **별도 검토·수정 없이 표준 양식에 그대로 반영**
- ❌ 위법 소지 = ①생성형 AI로 법률문서 작성 ②제휴 변호사 유료 검토 ③무료→유료 연결(알선)
- 법무부 유권해석: 내용증명·계약서 작성을 **유상** 수행 시 변호사법 제109조 위반 소지 (법무사도 불가)

### ★ 출력 경계 원리

**주어가 '법령·조문·산식'이면 정보, '귀하·귀하의 계약'이면 결론(위법).**

| ✅ 허용 | ❌ 금지 |
|---|---|
| 법 제6조의3 제1항이 정한 기간은 X~Y입니다 | 귀하는 X부터 갱신을 요구할 수 있습니다 |
| 오늘은 위에서 계산된 기간 범위 안의 날짜입니다 (평문 1줄만) | 지금 행사 가능합니다 / 지금 보내야 안전합니다 |
| 제7조 상한에 입력값 대입 시 105만원입니다 | 임대인의 110만원 요구는 위법이니 거부하시면 됩니다 |
| 묵시적 갱신 해당 여부는 본 서비스가 판단하지 않습니다 | 귀하의 계약은 묵시적으로 갱신되었습니다 |

### 🚫 금지 목록 (개발자가 무심코 넣기 쉬운 것)

1. **D-day 배지·카운트다운·신호등 UI** — 산술을 시각 언어로 결론화한 것 (초록불 = "가능합니다")
2. **푸시·이메일 자동 리마인더** ("기간이 곧 끝납니다") — 개별 사안 관리 = 사실상 상담
3. **거절사유 자가진단 문답** — 답을 받는 순간 포섭 판단이 된다. 9개 사유는 전원에게 조문 그대로만
4. **LLM 개입 일체** — 문구 다듬기·맞춤법 교정·"더 정중하게" 버튼 포함. 파이프라인 LLM 호출 0회를 코드리뷰 항목으로
5. 자유입력 placeholder에 법적 주장 예시문
6. **유료 구독 혜택표·가격표에 이 기능 기재** — 무료여도 대가성 프레임이 산다(109조 "받을 것을 약속")
7. **변호사 연결·"전문가 검토 완료" 표기** — 34조. 무료 연결도 알선으로 평가될 수 있다
8. 우편 발송 대행 부활 (우체국은 발송 API를 공개하지 않는다 — 조회 계열만 있다)
9. **"참고용 조언입니다"** — '조언'이라는 단어 자체가 상담 자인.
   허용어 = 정보·산식·서식·안내 / 금지어 = 조언·자문·상담·검토·진단·추천·가능합니다·유리·안전
10. **생성 문서를 DB에 저장** — 임대인·임차인 실명과 주소가 들어간다. 서버 미보관 원칙

### 체크리스트 설계 원리

전부 **"~임을 확인합니다"(이용자 선언)** 형식이다. 사실 질문("연체가 있습니까?") 형식으로 만들면
답변을 받아 우리가 포섭 판단을 한 구조가 된다.

- **주거용 확인만 게이트.** 차단 근거를 "귀하는 적용 대상 아님"(법적 판정)이 아니라
  **"서식의 전제"(제품 사양)** 로 프레이밍한다. 이 프레이밍이 핵심이다.
- **1회 소진은 미체크여도 진행 허용.** 여기서 차단하면 "귀하는 행사할 수 없다"는 판정을 우리가 한 것이 된다.

## 실무 설계 근거 (공인중개사 검토)

- **날짜는 "계약서상 만료일을 그대로 옮겨 적게" 한다.** 입주일·잔금일·시작일에서 만료일을 계산해 주면 사고가 난다.
  만료일 표기가 계약서마다 다르고("~2025.3.15.까지" vs "~2025.3.14.까지"), 하루 차이가 권리 소멸을 가른다.
- **통지서 톤**: 사무적·건조·정중. 경고성 문구("법적 조치"·"손해배상") 금지 —
  공격적이면 원래 실거주 의사가 없던 임대인도 실거주 거절(6조의3 1항 8호) 카드를 꺼낸다.
  단 **"제6조의3에 따라 갱신을 요구합니다"** 문장은 어떤 톤에서도 빠지면 안 된다.
  "계속 거주하고 싶습니다" 수준으로 쓰면 "희망사항이었지 권리행사가 아니었다"는 다툼이 실제로 난다.
- **발송은 문자/카톡이 1순위.** 내용증명을 첫 수단으로 쓰면 선전포고로 읽혀 관계가 깨진다.
  무응답·분쟁국면·마감 임박일 때만 내용증명 + **배달증명**(도달 증명은 내용증명이 아니라 배달증명이 한다).

# 추가 구현 (2026-08-13)

## PDF 다운로드 — `lib/renewal-pdf.ts` + `app/api/renewal/pdf`

🚨 **한글 PDF는 반드시 TTF + `subset:false`.** 조합별 실측 결과:

| 폰트 / 옵션 | 텍스트 추출 | **실제 렌더** | 크기 |
|---|---|---|---|
| NotoSansKR **.otf**, subset:false | FAIL (공백→`堺`) | ❌ 엉뚱한 한자로 깨짐 | 3,743 KB |
| NotoSansKR **.otf**, subset:true | OK | ❌ **한글이 아예 안 보임** | 36 KB |
| NanumGothic **.ttf**, subset:true | OK | ❌ 글자 군데군데 누락 | 10 KB |
| **NanumGothic .ttf, subset:false** | OK | ✅ 정상 | 731 KB |

- 원인: pdf-lib(fontkit)이 CJK **OTF(CFF)** 를 제대로 임베드하지 못한다. MuPDF 도 그 스트림을
  `FT_New_Memory_Face: unknown file format` 으로 거부한다.
- ★**텍스트 추출만으로 검증하지 말 것.** `otf+subset:true` 는 추출은 멀쩡한데 화면엔 아무것도 없다.
  반드시 PNG 로 렌더해서 눈으로 확인할 것.
- malgun.ttf 도 정상 동작하지만 **MS 윈도우 번들 폰트**라 PDF 임베드 배포 시 라이선스가 걸린다.
  **NanumGothic(SIL OFL)** 로 간다.
- 빈 줄에서 페이지 넘김을 판단하면 **백지 페이지**가 생긴다 → 페이지 분기는 '그릴 글자가 있을 때'만.
- 검증: A4 정확히 210.0 × 297.0 mm / 1페이지 / 브라우저 다운로드 시 한글 파일명 유지.

**같은 버그가 `lib/pdf-generator.ts`(대여약정서 PDF, 주력 기능)에도 있어서 함께 고쳤다.**
프로덕션에서 제목조차 안 찍히고 본문 한글이 전부 한자로 나오던 상태였다.

## 법령 변경 감시 — `lib/law-watch.ts` + `app/api/cron/law-check`

- **API 키 0개.** 법제처 공개 페이지를 HTTP 로 받아 파싱만 한다.
  - 조문: `law.go.kr/lsLawLinkInfo.do?lsJoLnkSeq=1007847519` (정적 HTML, 시행일·법률번호·조문 전문)
  - 교차확인: `easylaw.go.kr` 생활법령 페이지에 기간 문구가 살아있는지
- **감지만 하고 자동 반영하지 않는다.** 법이 바뀌면 계산 로직·경과규정은 사람이 검토해야 한다.
- **파싱 실패를 '이상 없음'으로 표시하지 않는다.** 실패 시 스냅샷을 덮어쓰지 않고
  `consecutive_failures` 를 올리며, 3회 연속 실패마다 메일. 화면은 3일 넘게 성공이 없으면 '지연' 표시.
- Vercel Cron 매일 20:00 UTC(= KST 05:00). ★**Vercel Cron 은 GET 으로 호출**하므로 GET/POST 둘 다 받는다.
- 테이블 `law_watch` (RLS enable + 정책 0개).

🚨 **`getLawStatusForDisplay()` 의 `noStore()` 를 지우지 말 것.**
supabase-js 는 내부적으로 fetch 를 쓰고, Next.js 가 그 응답을 **디스크 Data Cache**(`.next/cache/fetch-cache`)에
저장한다. 페이지에 `dynamic = "force-dynamic"` 을 걸어도 이 캐시는 살아남아
**서버를 재시작해도 옛 DB 값이 계속 나온다.** (실측으로 확인 후 `noStore()` 로 해결)
